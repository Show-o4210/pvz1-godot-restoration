# v1 还原问题与解决方案：可复用排查记录

整理日期：2026-10-05。本文汇总从 v0 进入 v1 后实际遇到的 UI、贴图、动画和动作切换问题，记录原因、当前实现和验证方式。规则适用于以后增加的角色与动画；仍保持现有三种植物和两种僵尸的阶段范围。

## 问题索引

| 看到的现象 | 确认的原因 / 原先缺失的处理 | 对应解决方式 |
| --- | --- | --- |
| 推车待机时轮子一直转 | 待机与启动共用持续推进的动画时钟 | 首帧显示后冻结，触发清场才推进动画 |
| 卡槽过大、费用和缩略图位置不协调 | 未统一原版卡片尺寸与点击区域 | 卡片、按钮均为 50×70，缩略图与遮罩在卡片内布局 |
| 草坪、角色落点和缩放不准确 | 网格原点、不同角色的贴图原点未分别对齐 | 草坪 y=80；按角色设置落点与阴影，保留部件原有变换 |
| 豌豆射击缺少反馈 | 发射逻辑尚未联动头部动作、前摇、声音与命中特效 | 播放原版射击段，0.35 秒前摇，按嘴部位置生成真实子弹 |
| 植物受伤表现弱 | 缺少短暂闪白和坚果分阶段破损 | 受击闪白后恢复，按 2/3、1/3 血量换破损图 |
| 僵尸没有断臂、掉头等表现 | 血量状态尚未驱动部件显隐与掉落 | 阈值触发断肢、残臂换图、掉落、无头衰减及死亡淡出 |
| 画面像加了暗色滤镜 | 着色器把已含贴图的 COLOR 再乘了一次贴图 | 直接使用 COLOR，验证零效果与默认渲染一致 |
| 豌豆头和身体各自摆动 | 独立头部动画没有继承茎部锚点 | 使用当前锚点 × 绑定锚点逆矩阵，统一头、嘴、眼皮和发射点 |
| 僵尸缺下巴 | 将 anim_head2 按编号误当成备用部件隐藏 | 按实际 Zombie_jaw.png 识别，掉头时才隐藏 |
| 僵尸匀速滑动、接触后停走生硬 | 世界位移独立于步态，接触和过渡处理不足 | 用 _ground 积分位移，截断接触距离，平滑过渡动作 |
| 啃咬后行走时手像反了 | 姿势恢复行走，但离散换图在混合时漏掉，残留啃咬手型 | 每帧同步目标动作的离散状态，再应用损伤覆盖 |
| 向日葵眨眼与摇摆脱节 | 眼皮使用眨眼段的固定坐标，没有继承脸部当前变换 | 眼皮绑定 anim_idle 的首帧基准，随脸部平移、缩放和旋转 |
| 点击阳光后直接消失 | 收集立即删除角色，没有单独的收集表现状态 | 移出可点击集合，在 HUD 上层飞回槽位并缩小，到达后清理 |

## 推车：把状态与动画时钟分开

**现象与原因。** 推车尚未启动，轮子已经持续旋转。初版在创建角色时播放动画，没有将“已显示待机姿势”和“正在运行动画”分开。

**解决。** `actor_view.gd` 在初始化后冻结推车；`game.gd` 在僵尸首次突破该行时解除冻结，同时启动移动和声音。冻结期间不推进动画相位，避免停止播放器时改变初始姿势。静态种子缩略图也使用同一冻结机制。

**验证与复用。** `presentation_test.gd` 检查待机一段时间后轮子角度不变、启动后角度变化，以及暂停会冻结共同动画时钟。以后遇到本应静止的机械部件，先检查谁在推进时间，而不是删除它的动画轨道。

## 卡片、草坪和角色落点：统一尺寸，分别校准原点

**现象与原因。** 卡片过大，种植区域和角色位置存在偏差。原版资源带有自己的尺寸与部件坐标，不能用一套统一偏移或任意缩放兼顾 UI、植物、僵尸和推车。

**解决。** `game.gd` 将卡片纹理和点击区设为原版 50×70，费用、静态缩略图、冷却遮罩在该区域内定位。草坪采用原点 `(80, 80)` 和 80×100 格子，植物、僵尸、推车分别使用自己的落点；推车使用 0.85 缩放。角色部件保持转换时的原版变换，额外增加地面阴影。

**验证与复用。** 卡片可见尺寸必须和点击区一致；第五行仍须完整可种植。视觉上检查脚底/根部与阴影的相对位置。先分清逻辑格子、角色根节点、部件原点和 UI 点击区，再调整对应的一层，避免通过改碰撞位置补偿贴图偏移。Sprite2D 的 `centered=false` 是导入坐标约定的一部分。

## 射击反馈：按动作相位生成子弹

**现象与原因。** 初版虽然有可命中的飞行豌豆，但射手动作、声音和命中反馈不足。玩法正确并不等于表现完整。

**解决。** 身体待机与头部射击分别播放，射击段按 35 fps 推进；0.35 秒前摇结束后，在当前动画嘴部坐标生成一颗子弹。加入发射音、命中音、闪白和原版豌豆碎屑。多声道音效池允许同帧多个声音播放。头部绑定的具体方法见下文。

**验证与复用。** `presentation_test.gd` 检查先播放射击、前摇内没有子弹、前摇后只生成一颗、子弹高度跟随嘴部、射击结束回待机且叶子与身体不被隐藏。`gameplay_test.gd` 检查真实子弹飞行、分行判定和首先遇到的目标命中。以后增加攻击动作时，共用模拟时钟协调前摇、出弹、声音和命中，不能另外启动不受暂停控制的定时器。

## 植物伤害：短暂反馈与持久破损分别管理

**现象与原因。** 只有血量下降，难以看出受到攻击；坚果缺少低血量外观。

**解决。** 受击触发 0.25 秒衰减闪白，保留原有透明度；坚果低于 2/3、1/3 血量时分别使用原版两档裂纹图。闪白属于短暂效果，破损属于持久状态，后者在推进原版动画后重新应用。颜色错误及其验证见下文。

**验证与复用。** 检查受击开始和结束两端、两档裂纹图、暂停时效果不继续消退。临时效果结束必须恢复基线；持久破损不能被待机动画的原始贴图覆盖。

## 僵尸断肢：损伤状态拥有最终显隐权

**现象与原因。** 缺少断臂、掉头、残臂外观和死亡过程；加入这些表现后，还需要防止换动作把已经消失的部件显示回来。

**解决。** 本项目普通僵尸身体血量为 200，护甲先吸收伤害；身体血量低于 2/3 断臂，低于 1/3 掉头。使用原版掉落部件和残臂图，无头状态停止啃食并逐渐衰减血量，死亡后播放倒地并淡出。路障按剩余护甲换三档破损图。`apply_damage_parts()` 在动画状态同步之后执行，最终决定受损部件的可见性和替代贴图。

**验证与复用。** 检查阈值、掉落部件、切换动作后断臂仍隐藏、无头不再啃食、结算后尸体完成淡出。先保留当前部件姿势生成掉落，再隐藏活体上的对应部件。掉落运动和弹跳目前是简化实现，不代表粒子系统已逐像素还原。

## 颜色必须有“零效果等于原图”的基线

Godot 的 CanvasItem `fragment()` 输入 `COLOR` 已经包含贴图、节点染色与透明度。再次乘 `texture(TEXTURE, UV)` 会把颜色和透明度平方，中间色变暗，半透明边缘变薄。

`hit_flash.gdshader` 直接基于 `COLOR` 叠加短暂闪白，保留 alpha。不要用全局提亮来补偿这个错误：那会同时破坏背景与 UI 的正常颜色。

新增着色器后，用真实 GPU 将零效果状态与默认 Sprite2D 渲染逐像素比较。覆盖纹理 alpha、节点染色、父节点透明度和受击后的恢复。`tests/color_render_test.gd` 是可复用的检查入口；本轮四组 RGBA 对照最大误差均为零。

表现预览优先保留 PNG 或全彩视频。GIF 调色板可能改变颜色，不能作为颜色验收基准。

## 独立动作仍然需要共同锚点

头部、嘴、眼皮分别有动作，不意味着它们可以脱离身体坐标。原版豌豆射手把头部动画附着到身体的 `anim_stem`。

使用 [reanim_attachment.gd](../scripts/reanim_attachment.gd) 建立部件容器并重新指向 AnimationPlayer 的轨道。每帧应用相对绑定姿势：

```text
部件世界姿势 = 角色世界姿势 × 当前锚点 × 绑定锚点的逆矩阵 × 部件局部动画
```

这同时继承平移、旋转、缩放和倾斜，不需要反复修改贴图坐标，也不会累积偏移。头部、嘴、眼皮和发射点都进入同一容器；射击结束后，头部待机相位重新对齐身体。不要把已经包含身体摆动的合成头部动画再叠加锚点，否则会重复摆动。

## 向日葵眨眼：独立时钟，共同脸部坐标

**确认的原因。** 向日葵的 `anim_idle` 同时是待机段标记和实际脸部贴图轨道。脸部在待机段不断改变位置与纵向缩放，而三帧眨眼段的 `anim_blink` 使用约 `(27.1, 25.1)` 的固定原始坐标。之前只拆出了眼皮播放器，忽略了原版 `AttachBlinkAnim()` 到 `anim_idle` 的附着，所以脸部摇摆时眼皮会留在原地。

**解决。** 复用 `reanim_attachment.gd` 创建 `FaceAttachment`，以待机首帧脸部变换为绑定基准，将眼皮节点及身体、眨眼播放器的对应轨道一起改到容器下。眼皮保留独立的动作时钟、换图和结束显隐；每帧由“当前脸部矩阵 × 首帧脸部逆矩阵”跟随脸部。绑定基准只在初始化时取一次，不能在每次眨眼时重取，否则又会丢掉当时的摇摆偏移。也不能仅绑定到茎部，因为葵花脸还有自身的伸缩。

**验证与复用。** `tests/blink_alignment_test.gd` 共 33 项，覆盖五个身体相位、三帧眼皮贴图、跨待机循环、暂停/恢复、眨眼结束，以及脸部和角色的旋转缩放。修复前的空间对齐检查失败，修复后全部通过。`tests/capture_blink.gd` 生成三个不同摇摆相位的四秒全彩近景，保存在本地 `build/sunflower-blink.mp4` 和 PNG。其他表情叠层出现漂移时，先确认贴图的作者坐标和正确的脸部锚点，再处理动作节奏。

## 用素材语义决定部件显隐

`anim_head2` 对应的是 `Zombie_jaw.png`，属于下巴。不能凭轨道编号把它当成备用头部隐藏。

先核对轨道实际贴图和原版显隐规则。配饰、断肢和动作自身的显隐需要明确区分。下巴正常参与行走与啃食；掉头时，头、下巴和舌头一起隐藏。每次切换动作后重新应用损伤状态，避免动画重新显示断肢。

## 位移跟随步态，而非独立匀速平移

原版僵尸的 `_ground` 是不绘制的参考轨道，却参与移动计算。转换时不能因为没有贴图就丢掉它的运动语义。

`tools/prepare_assets.py` 将原始轨道导出为 `assets/actors/zombie_motion.json`；[reanim_motion.gd](../scripts/reanim_motion.gd) 对其插值并跨循环累计位移。最后一帧按原版保持，循环重置不产生反向跳位。

行走动画速率由一周期的距离和目标平均速度计算。本轮保留平均 12 px/s，帧间速度随原版脚步变化。世界位移与显示姿势使用同一动画相位；先计算逻辑移动，再推进到对应显示姿势。

接触植物时截断位移，并只对剩余接触时间计啃食伤害。行走、啃食和恢复行走之间使用 0.18 秒姿势混合。动画、命中判定和世界坐标不能使用相互独立的假位置；暂停也必须停住这一共同时间线。

## 手部方向异常：连续姿势与离散状态分开处理

**复现。** `capture_detail.gd` 中路障僵尸先啃咬坚果，第 4 秒移除坚果，随后恢复行走。旧预览后半段出现手型反向的观感。

**确认的原因。** 原始 `Zombie.reanim.compiled` 的行走段使用 `Zombie_outerarm_hand.png`（下垂手），啃咬段使用 `Zombie_outerarm_hand2.png`（张开手）。转换结果已在两个动作的第 0 秒分别写入正确贴图。运行时 0.18 秒混合能更新位置、旋转和缩放，但离散贴图更新会受旧动作影响，留下啃咬手型。于是出现“行走变换 + 啃咬贴图”的组合。核对原版矩阵和 Godot 变换后，基础旋转转换公式一致；本例不是镜像素材或角度符号错误。

2026-10-05 在本机 Godot 4.7.2 的临时对照结果：

| 尝试 | 啃咬 → 行走结果 | 使用决定 |
| --- | --- | --- |
| 保留 0.18 秒混合，仅 play 后 advance(0) | 啃咬手型残留 | 原问题 |
| 关闭混合 | 换图正确，但失去已有平滑过渡 | 仅用于定位原因 |
| 混合期间 seek(0, true) | 仍残留 | 不采用 |
| 改离散混合设置为 DOMINANT 或 FORCE_CONTINUOUS | 本例仍残留 | 不作为修复 |
| 在推进后显式采样目标动作的离散状态 | 换图正确，姿势继续混合 | 当前实现 |

**解决。** [reanim_discrete_state.gd](../scripts/reanim_discrete_state.gd) 根据当前动作与相位，读取每条启用的离散值轨道，应用“时间不晚于当前相位的最后一个关键帧”。它支持嵌套部件路径、段内换图与显隐；不会提前应用未来关键帧。只处理持久值状态，不接管方法、声音等事件轨道。`actor_view.gd` 在切换动作和每次推进身体、头部、眼皮播放器后调用它。

只在切换瞬间换图不足以保证正确，因为混合期间旧动作仍可能再次写入状态。当前每帧的顺序为：

```text
推进动作时钟 → 混合连续姿势 → 同步目标动作的离散状态
→ 同步部件锚点 → 应用血量/断肢等游戏状态覆盖 → 渲染
```

**验证与复用。** `discrete_state_test.gd` 包含 36 项检查：四个不同行走相位下反复切换，过渡内与过渡后的手型，完整步态循环，身体姿势仍平滑，真实植物接触/移除流程，断肢/掉头覆盖，以及嵌套路径和段内离散关键帧。以后出现“某部件方向错误”，同时检查贴图身份与变换数据；单看旋转角度或导出的动画文件不能证明播放结果正确。

## 阳光收集：逻辑入账与飞行动画分别管理

2026-10-06：点击阳光时继续立即入账一次，保留既有经济时序；原角色移出 `suns`，进入 `sun_flights`，免于再次收集、掉落和寿命回收。按距离使用 0.35–0.75 秒缓动，飞向阳光槽并缩小，到达时清理并短暂强调数字。多颗阳光各自保存起点和时钟，不相互覆盖。

角色必须进入高于种子栏的独立 CanvasLayer；仅增加世界节点的 z_index 无法越过 HUD 的 CanvasLayer。动画使用共同模拟时钟，暂停时冻结；胜负后未结束的飞行仍由表现时钟完成，避免留下角色。`tests/sun_collection_test.gd` 通过 12 项入账、防重复、图层、缩放、寿命、暂停、并发和结算清理检查。全彩预览由 `tests/capture_sun_collection.gd` 生成，保存在本地 `build/sun-collection.mp4`。

## 可复用的排查顺序

1. 固定复现条件：种类、受伤状态、动作、相位、帧率，以及是否经历过动作切换。保留 PNG 或全彩视频。
2. 从异常部件追到实际贴图、轨道和节点路径。核对图像语义，不按文件编号猜用途。
3. 对比原始动画数据、转换后的轨道值和运行时节点值。尤其打印 texture、visible、transform 与当前动作/相位。
4. 逐层隔离：默认材质对照着色器；静态动作对照动作切换；零混合对照混合；动画原始状态对照损伤覆盖。
5. 在拥有该状态的一层修复。颜色归材质，身体绑定归锚点，步态归位移，离散换图归状态同步，损伤归游戏状态。
6. 补充会在修复前失败的检查，并验证切换瞬间、过渡中、过渡后、重复切换和暂停；检查完成后再更新视觉预览。

社区工具的语义校验仍有价值，但它主要比较转换数据与自身采用的规则，不能取代真实播放的状态检查、独立数学对照和 GPU 渲染检查。
